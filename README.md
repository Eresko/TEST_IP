## Описание

Тестовое задание на Laravel 12, обеспечивающее высоконагруженную работу со слотами: получение доступных временных слотов с пагинацией, отказоустойчивое создание холдов (бронирования) с защитой от оверсела, асинхронную обработку и полное управление жизненным циклом брони (подтверждение и отмена) с уведомлениями через веб-сокеты.

В проекте применен комплексный подход к оптимизации Highload-нагрузок: механизм **Double-Checked Locking** защищает БД от (Cache Stampede) при чтении. Конкурентный **атомарный инкремент/декремент в KeyDB** в связке с очередями и пессимистичными блокировками БД (`lockForUpdate`) гарантирует 100% защиту от избыточного бронирования (Overselling) при записи.

Фронтенд получает мгновенный ответ `202 Pending` при создании запроса, а управление финальными статусами транзакций защищено двухэтапными проверками бизнес-логики.

Создание холда — это точка пиковой конкурентной нагрузки (Race Condition за остаток мест), 
поэтому мы вынесли её в многопоточный KeyDB и очереди, чтобы разгрузить СУБД. 
Подтверждение же происходит на уже зарезервированном месте, трафик там в разы ниже, 
а строгая согласованность данных в мастер-базе для финального подтверждения важнее,
чем микросекундный ответ


## Резюмируем
### Слой данных
1. **Enums** (`HoldStatus`) обеспечивают строгую типизацию состояний бронирования (`HELD`, `CONFIRMED`, `CANCELLED`).
2. **DTO** (`SlotAvailabilityDto`, `CreateHoldDto`) инкапсулируют параметры запросов (пагинация, сортировка, ключ идемпотентности), изолируя бизнес-логику от сырого HTTP-ввода.
3. **KeyDB Хранилище** используется в качестве сверхбыстрого in-memory слоя. За счет своей многопоточной архитектуры KeyDB эффективнее классического Redis справляется с пиковым потоком конкурентных запросов.

### Слой логики
1. **SlotService** управляет созданием холдов, асинхронными очередями и интеграцией с KeyDB. Защищает от оверсела на этапе Pre-Hold через атомарный `Cache::decrement`.
2. **HoldService** инкапсулирует логику финальной стадии жизненного цикла бронирования. Отвечает за безопасное подтверждение (`confirmHold`) и отмену (`cancelHold`) холдов.
3. **Double-Checked Status Locking**: В `HoldService` проверка статуса происходит дважды — до блокировки (для быстрого выхода) и строго внутри транзакции после `lockForUpdate()`. Это исключает подмену данных, пока процесс ожидал освобождения строки в БД.
4. **Пессимистическая блокировка**: При операциях смены статуса строки `Slot` и `Hold` жестко блокируются через `lockForUpdate()`, предотвращая любые параллельные изменения данных.
5. **Своевременная инвалидация**: Любое финальное изменение статуса брони (успешный холд, подтверждение, отмена) триггерит сброс страниц кеша пагинации слотов по маске `slots_availability_page_*` напрямую в KeyDB.

### Асинхронность и Очереди
1. **Job** (`ProcessGeodistributedHold`) выносит логику фиксации бронирования в фоновый режим. Бекенд отдает клиенту мгновенный ответ со статусом `202` без ожидания выполнения тяжелых операций.
2. **Инфраструктура** Фоновые воркеры разбирают задачи изолированно в выделенной очереди `hold_processing`.

### Реактивность
1. **HoldStatusUpdated (Event)** Фиксирует результат обработки фонового холда.
2. **Веб-сокеты** Транслируют статус (`HELD` или `failed`) напрямую на клиент по ключу идемпотентности. Это избавляет фронтенд от необходимости слать постоянные опрашивающие (polling) запросы к API.

### Инфраструктура
1. **Контейнеризация** позволяет развернуть весь проект со всеми зависимостями (PHP, Nginx, DB, KeyDB, сокет-сервер) одной командой `docker compose up -d --build`.

## Структура Docker

Файл `docker-compose.yml` содержит шесть основных сервисов:

1. **ak_techlogistic_php** (`ak_techlogistic`) – PHP-контейнер с Laravel 12.
2. **ak_techlogistic_nginx_server** (`ak_techlogistic_nginx`) – Веб-сервер Nginx для маршрутизации HTTP-трафика (доступен по порту `3100`).
3. **ak_techlogistic_queue** – Выделенный контейнер воркера для асинхронного разбора задач из RabbitMQ.
4. **ak_techlogistic_postgres_db** (`ak_techlogistic_postgres`) – Реляционная база данных PostgreSQL 14 для хранения слотов и логов холдов.
5. **ak_techlogistic_rabbitmq_server** (`ak_techlogistic_rabbitmq`) – Брокер сообщений RabbitMQ для надежной обработки очередей.
6. **ak_techlogistic_keydb_server** (`ak_techlogistic_keydb`) – Многопоточный KeyDB-сервер для хранения атомарных счетчиков слотов (`slots:{id}:remaining`), распределенных блокировок (`Cache::lock`) и кэша.

## Быстрый старт (Docker)

1. **Клонируем проект**
   ```bash
   git clone <репозиторий>

   ```

   docker compose up -d --build
